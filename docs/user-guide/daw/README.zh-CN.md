# 通过 DAW 测量：通用流程

状态：**流程草案，2026-09-22。** 本文件夹里每个 DAW 的方案都遵循这些步骤，只补充该 DAW 自己的菜单与陷阱。
方案在 [../../DAW_COMPATIBILITY.md](../../DAW_COMPATIBILITY.md) 中对应行变绿之前都标为 DRAFT；
草案依据厂商文档编写，在矩阵测试时逐行确认。英文版：[README.md](README.md)。

RoomScope 从不与 DAW 通信。它写出扫频 WAV，DAW 播放并录制，RoomScope 读取导出（或录下）的文件。
所以 DAW 兼容只关乎三件事：扫频必须**原样**到达声卡（不转换采样率、不拉伸、不经过插件），
录音必须**完整且未经处理**地回来（不归一化、不抖动、不裁剪），RoomScope 必须**读得了 DAW 写出的文件**。

## 0. 开始之前

* **一台声卡，一个时钟。** 监听音箱接声卡主输出；测量麦克风接输入 N。自带时钟的 USB 麦克风是另一种情况（见硬件指南），不要从它开始。
* **处处采样率一致。** 在 DAW 的音频设置或声卡控制软件里设定声卡采样率，用同一采样率新建工程，并用**完全相同**的采样率生成扫频：
  `roomscope sweep --sample-rate 48000 --out sweep_48k.wav`（GUI 会显示声卡当前采样率）。这样 DAW 里什么都不需要转换。
* **sidecar 与 WAV 放在一起。** `sweep_48k.roomscope-sweep.json` 让 RoomScope 精确重建参考信号；不要改名、不要分开。
* **第一次播放前把监听电平调低。** 扫频默认峰值 −12 dBFS；只有在录音太小时（RoomScope 会告诉你）才在两次测量之间逐步提高监听电平。

## A. 先做链路检查（每个 DAW + 声卡组合做一次）

电气回环：DAW 把扫频从声卡输出播出，声卡通过一根线（或声卡自带的 loopback 功能）直接录回输入。不接音箱、不接麦克风。
期望结果精确已知，所以 RoomScope 发现的每个缺陷都属于 DAW、导出或声卡。

1. 接线：输出 N → 输入 M（TRS 或 XLR 线），或在声卡控制软件里启用 loopback 输入并把它作为录音输入。
2. 以声卡采样率新建工程。把扫频 WAV 不经转换地导入轨道 1。按该 DAW 方案设置**"不拉伸"**相关选项（这是最容易出错的一步）。
3. 轨道 2：单声道音频轨，输入 = 回环输入，录音预备，**关闭输入监听**。
4. 轨道 1 → 主输出。主总线上**什么都不放**，监听路径上也什么都不放（没有限制器、EQ、房间校正、响度补偿）。
5. 把播放头放在扫频区域之前，开始录音，扫频结束约三秒后停止。只播放一次。
6. 把录音取出来（见"导出规则"）：最好直接用工程音频文件夹里的录音文件；否则导出轨道 2。
7. 运行检查：

   ```bash
   roomscope check --recording loop.wav --sweep sweep_48k.wav --daw "Logic Pro 11.2"
   ```

   期望 `PASS`。若 `FAIL`，每条未通过的判据都会说明可能原因（被拉伸、被重采样、有插件、削波、播放了两次……）——修正后重复直到通过。链路检查不通过就不要测房间。

## B. 房间测量

同一工程、同样的轨道。拔掉回环线，麦克风接输入 M，打开监听音箱，把麦克风放在你录音的位置。录一次，取出文件，然后：

```bash
roomscope analyze --recording take1.wav --sweep sweep_48k.wav --out session1/ --profile vocal
```

（或在 GUI 里 *Import Recording* → *Analyze*）。RoomScope 会对这段录音再做一次完整性校验。

## 导出规则（所有 DAW）

| 规则 | 原因 |
| --- | --- |
| 优先直接用工程音频文件夹里的**录音文件本身**（Logic：Project Audio 浏览器；Studio One：Pool；Cubase：Pool → "Show in Finder"） | 它没经过任何处理 |
| 若导出：**WAV，32 bit float**（关掉抖动时 24 bit 也可以） | 浮点不会削波，也不需要抖动 |
| **关闭归一化**、关闭抖动、不用"过载保护" | 电平变化无害，但抖动与归一化不是你测到的东西 |
| 导出**整个 take**，不裁剪 | RoomScope 自己找扫频；扫频前的静音就是噪声测量 |
| 单声道或立体声都可以；导出轨道与主总线上**没有插件** | 限制器或 EQ 不是房间 |
| AIFF / CAF / BWF / FLAC 也能读；MP3 / AAC 会被拒绝 | 有损编码会毁掉扫频 |

## 对所有 DAW 都适用的陷阱

* **跟随速度的片段**（warp / flex / elastic / musical mode / stretch）：扫频被时间拉伸。RoomScope 报告"被时间拉伸 x %"。
* **导入或导出时的采样率转换**：干净的转换 RoomScope 能处理，但以错误速度播放的文件会被拒绝（"错速播放 x %"）。
* **Varispeed / 加速控件**：症状与转换相同。
* **主总线或监听路径上的插件**：链路检查里出现谐波失真或不平坦的响应。
* **麦克风轨道开着输入监听**：麦克风信号在录音时被送到监听音箱——反馈回路与被染色的测量。
* **循环播放、带节拍器的预备拍、一个文件里两个 take**：多个扫频通过；RoomScope 分析最强的一次并注明。
* **蓝牙或系统音频输出**而不是声卡：链路检查在带宽与失真上失败。

## 兼容矩阵要记录的内容

DAW 名称与准确版本、macOS 版本、声卡型号、采样率、文件获取方式（录音文件或导出及其设置）、链路检查判定、日期、执行人。
